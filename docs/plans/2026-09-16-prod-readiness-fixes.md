**Критерий готовности.** Посторонний человек ставит панель на чистый хост по README, получает этот форк, заводит владельца, поднимает стек, обновляет панель и откатывает ее назад - и ни на одном шаге не встречает upstream Dockge. До этого момента прод-тест проверяет не тот продукт.

## Очередь 1. Без этого прод-тест бессмысленен

### A. Вернуть e2e в зеленое

Прогон от 2026-09-16: 27 прошли, 13 упали. Ни одно падение не означает, что панель не работает - тесты описывают интерфейс, которого больше нет. Разбор по причинам:

| # | Тест | Причина | Что делать |
| --- | --- | --- | --- |
| A1 | `auth.spec.ts`, 3 теста | форма входа переразмечена | `#floatingInput` -> `#login-identifier`, `#floatingPassword` -> `#login-password`, `.form-container` -> `.auth-card` |
| A2 | `stack-status.spec.ts`, 2 теста | состояние в строке стало точкой с невидимой подписью внутри `Uptime`, слова другие | брать состояние из `.state-chip .label` (или по `aria`), словарь - `running` / `attention`, а не `active` / `inactive` |
| A3 | `stack-list-row.spec.ts`, 1 тест | класс переименован | `.reason-badge` -> `.attention-badge` |
| A4 | `stack-inspector.spec.ts` (телефон), 1 тест | класс исчез | `.create-heading h1` -> `h1` страницы создания (`NewStack.vue`) |
| A5 | `stack-inspector.spec.ts`, 2 теста | меню сервиса и настройка колонок открываются иначе | разобрать по DOM: `.service-menu > summary`, `.table-options > summary` на месте, изменилось поведение раскрытия |
| A6 | `stack-terminal.spec.ts`, `container-terminal.spec.ts`, 2 теста | вкладки терминалов и отметка выбранной оболочки перестроены | разобрать по DOM: `.terminal-tab` на месте, `.badge` с именем оболочки - нет |
| A7 | `mcp.spec.ts`, 1 тест | разметка ключей MCP изменилась | разобрать по DOM |
| A8 | `stack-journal.spec.ts`, 1 тест | **продуктовая развилка, а не тест** | см. ниже |

**A8 - единственное место, где спорит не тест, а поведение.** Тест проверяет: смотришь журнал стека A, выбираешь стек B - видишь журнал B. Сейчас строка списка ведет на `/stack/<имя>` без вкладки (`StackListItem.vue`, `url()`), поэтому журнал закрывается и открывается обзор. Предлагаемое решение: сохранять текущую вкладку при переключении стека - человек, читающий журналы, переключает стеки именно чтобы читать журналы, и возврат на обзор каждый раз стоит ему двух лишних действий. Если решение принимается, меняется `url()`, а тест остается как есть; если нет - тест переписывается под новое поведение и в журнал плана пишется, почему.

**Критерий приемки A:** `npm run test:e2e` зеленый; каждый измененный тест доказывает то же свойство, что доказывал раньше. Ослаблять проверку, чтобы она прошла, нельзя: если свойство исчезло вместе с элементом, тест переписывается под новое свойство, и это отмечается в журнале.

**Оценка:** 3-4 часа, из них половина - A5-A7, где нужен разбор по живому DOM.

## Очередь 2. Образ и раздача

### D. Свой базовый образ

`docker/Dockerfile` собирается от `louislam/dockge:base` и `louislam/dockge:build-healthcheck`. Оба рецепта лежат в репозитории (`docker/Base.Dockerfile`, `docker/BuildHealthCheck.Dockerfile`), но образы тянутся чужие. Развилка:

1. собрать свои и назвать своим пространством имен - быстрая сборка, но нужен один разовый прогон и место, куда их класть;
2. втянуть базу стадией в сам `Dockerfile` - никакой внешней зависимости, но каждая сборка ставит `docker-ce-cli` и `docker-compose-plugin` заново.

Рекомендация: вариант 1, потому что сборка образа - частая операция, а базовый слой меняется раз в год.

**Оценка:** 1 час.

### E. Вычистить образ

`COPY . .` кладет внутрь `docs/` (3.1 МБ), `test/` (3.7 МБ, вместе с эталонными снимками) и `extra/seed-review.ts` - скрипт приемки, который ставит `disableAuth`. Ему в образе не место.

Добавить в `.dockerignore`: `docs`, `test`, `extra/seed-review.ts`, `playwright*.config.ts`, `.github`.

**Критерий:** в образе нет ни одного файла приемки и тестов; панель работает так же.

**Оценка:** 15 минут.

### F. Кэш статики

`expressStaticGzip("frontend-dist")` отдает хешированные ассеты с `Cache-Control: public, max-age=0` - браузер переспрашивает каждый файл при каждой загрузке. Имя файла уже содержит хеш, поэтому `/assets/` можно отдавать как неизменяемый на год. Осторожно: `manifest.json`, `icon.svg` и иконки не хешированы, им долгий срок вреден.

**Оценка:** 30 минут вместе с проверкой заголовков.

## Очередь 4. Сам прод-тест

Сценарий, который и будет ответом на вопрос "готово ли":

1. чистый хост, только Docker; `git clone` по тегу, `.env` из примера;
2. `npm run build:frontend`, `docker compose up -d`; панель отвечает, healthcheck зеленый;
3. первый вход: код из `data/bootstrap-token`, создание владельца, проверка прав `0600`;
4. создание стека из `docker run`, запуск, журнал, консоль сервиса, секрет;
5. правка compose руками на диске - панель видит изменение;
6. обновление панели: `npm run update-docker`, состояние и стеки на месте;
7. откат на предыдущий тег образа - данные читаются;
8. перезагрузка хоста - панель и стеки поднимаются сами;
9. за прокси с TLS: вход, сессия, websocket, терминал.

**Оценка:** 2 часа на хосте.
