# Dockge2 0.0.15

This release makes installation one line and lets the installer and the updater say what they are
doing. They print their checks in sections with the result of each, give a hint under every
problem, and end a fresh installation with the address of the panel and the setup code. The panel
itself is unchanged.

## Installing

```bash
curl -fsSL https://github.com/mazixs/dockge2/releases/latest/download/install.sh | sudo bash
```

- The installer checks the host, verifies the signed release and shows the plan, then asks
  `Install 0.0.15? [y/N]` on the terminal. Nothing is written and no image is pulled before the
  answer; `n` ends with "Cancelled: nothing was installed or changed."
- Options go after `bash -s --`, for example `| sudo bash -s -- --port 8080`. Without a terminal,
  as in a provisioning script, the installer stops before any change and points to `--dry-run` and
  `--yes`.
- The script is one block that bash reads in full before it runs any of it, so a download cut short
  runs nothing.
- To read the installer before it runs, see
  [installation](https://github.com/mazixs/dockge2/blob/v0.0.15/docs/installation.md#reading-the-installer-first).

## Updating

From Settings -> About, or on the host; use the actual installation directory:

```bash
sudo /opt/dockge2/.dockge2/update --version 0.0.15 --dry-run
sudo /opt/dockge2/.dockge2/update --version 0.0.15 --yes
```

The database and the stack files do not change. The update is run by the installed 0.0.14 updater,
so it still prints the old text; the new output starts with the next update, or right away with
the new installer and `--bootstrap --update`. See
[updating](https://github.com/mazixs/dockge2/blob/v0.0.15/docs/updating.md).

## What the installer and the updater print

- **Host**: Linux on amd64 or arm64 and the `curl`, `sha256sum` and `docker` commands. Every unmet
  requirement is listed at once with its fix, before anything is downloaded. A host without Docker
  used to stop at `Required command: docker`.
- **Updater**: the pinned Cosign checksum and the signature of the updater. The verifier's own
  "Verified OK" is no longer printed.
- **Docker**: a local daemon, the Engine and Compose versions and the Compose plugin, compared with
  what the release needs before the plan is shown. Docker is still not run before the updater's
  signature is checked.
- **Release**, **Plan**, then each step of the installation, update, rollback or `--resume`. A
  failure names the step, its cause and a hint, and the last line says where the installation
  stands. When an update fails after the panel was stopped, a **Recovery** section shows how the
  previous version came back.
- **Done** of a fresh installation lists the host's addresses with the port, the setup code for the
  owner account and the command for later updates. The code itself is shown on a terminal only;
  captured output, such as a provisioning log, gets the command that reads it.
- Colour, and a running step that its result replaces, only on a terminal without `NO_COLOR`.
  Problems go to stderr.

The web interface is not affected: with `--progress json` stdout carries only the JSON lines, as in
0.0.14.

## Uninstall

The image commands no longer report an error when there is nothing to remove, as on an
installation that was never updated.
