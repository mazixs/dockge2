# Dockge2 0.0.10

This release introduces verified host installation and self-updates. Release installs use signed
metadata, authenticated updater binaries and an image pinned by digest. They never fetch deployment
files from `main` or fall back to a source build when a download fails.

## Installation and migration

Download and review `install.sh` attached to this release. On the Docker host:

```bash
sudo bash /tmp/dockge2-install.sh --dir /opt/dockge2 --version 0.0.10 --dry-run
sudo bash /tmp/dockge2-install.sh --dir /opt/dockge2 --version 0.0.10 --yes
```

Existing installations must use the new released bootstrap with `--update --dir /existing/path`.
Supported legacy import starts from the released `0.0.8` configuration. Custom vendor files and
unrecognized local builds are refused; preserve local edits and follow the migration guide.
After migration, use `/existing/path/.dockge2/update`. Old checkout scripts are not rewritten.

See [installation and updates](https://github.com/mazixs/dockge2/blob/v0.0.10/README.md) and
[trust, migration and recovery](https://github.com/mazixs/dockge2/blob/v0.0.10/docs/self-updates.md).

## Reliability

- Durable operation journal, project/data locks, image identity checks and application readiness.
- Stopped-data backup with integrity checks and schema-aware recovery. Restoring data requires
  explicit `--rollback --restore-data`; newer data is preserved separately.
- Bootstrap interruption reaches the updater and waits for recovery before removing temporary tools.
- Release publication tests both image architectures before moving the stable channel.

## WebUI

Release checks distinguish network failures, deadlines, GitHub request limits, invalid responses
and channels without a complete release. Stack updates distinguish download, build and container
application failures. Busy commands receive an immediate response. An interruption or lost response
is not shown as success. Buildable service images are built instead of being unnecessarily pulled.

## Repository hygiene

Personal workstation paths and contact/preview details were removed from the current documentation.
Environment variants and local browser-session files are excluded from Git and Docker build context.
Public project coordinates and license attribution remain intact.

## Release gate correction

The unpublished `v0.0.9` candidate passed the amd64 migration and recovery gate, but the classic
Docker image store rejected pulling the arm64 variant under the same index digest. The gate now
removes only its own fixture image references after fixture containers are gone, without forced
image removal, before testing the next architecture. The original tag remains unchanged.
