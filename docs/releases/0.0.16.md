# Dockge2 0.0.16

This release lets the panel create a deploy key for a private Git repository, helps configure
stacks whose env files are not in Git, and makes an interrupted first installation repeatable.

## Private repositories

On New stack -> From Git, enter an SSH address such as `git@github.com:owner/repository.git` and
choose **Create a deploy key**. Add the displayed public key to the repository with read access
only, then load the branches and deploy. Links open the deploy key settings on GitHub, GitLab and
Bitbucket.

The private key stays in the panel's data directory with `0600` permissions. The repository uses
the same key for cloning and later updates, without adding a mount to an existing installation.
An access refusal and an unknown SSH host key have separate messages; an existing stack can show
its public key again when access is denied. Other Git hosts need a trusted `known_hosts` entry.
HTTPS tokens are not supported. See
[private repositories](https://github.com/mazixs/dockge2/blob/v0.0.16/docs/git-stacks.md#private-repositories).

## Env files in Git stacks

When a repository contains `.env.example` but Compose needs `.env`, the stack is saved without
starting, and the result names the missing file. **Create .env from .env.example** copies the
example only on request, with `0600` permissions, and opens the files for editing. It never
overwrites an existing file. Fill in the values before starting the stack.

Applying a Git update also preserves the chosen files when the environment still needs values,
and reports that the stack has not started. Reading a Git commit now uses one batch operation
instead of a separate process for each file.

## Interrupted installation

If a first installation stops after writing `.env` but before starting the panel, repeat the same
install command. The installer recognises that unfinished preparation and continues. Different
options are refused when they would change the saved `.env`.

## Updating

Update from Settings -> About, or on the host using the actual installation directory:

```bash
sudo /opt/dockge2/.dockge2/update --version 0.0.16 --dry-run
sudo /opt/dockge2/.dockge2/update --version 0.0.16 --yes
```

There are no database migrations in this release. See
[updating](https://github.com/mazixs/dockge2/blob/v0.0.16/docs/updating.md) for older installations.
