## Конвертация docker run

В `frontend/src/components/CreateStackSheet.vue` уже реализован следующий путь:

1. Человек вставляет Compose или команду в общее поле. `docker run` и `sudo docker run` распознаются автоматически после паузы 400 мс.
2. Обработчик `composerize` в `backend/socket-handlers/main-socket-handler.ts` преобразует строку команды в Compose. Саму команду Docker этот обработчик не выполняет.
3. Форма показывает полученный YAML и предлагает имя стека по контейнеру или сервису, если человек еще не ввел имя самостоятельно.
4. `common/docker-run-flags.ts` составляет отчет: параметры перенесены, требуют проверки или не перенесены. Первый потерянный параметр виден сразу; остальные раскрываются.
5. Можно вернуть исходную команду, отредактировать результат, выбрать агент и затем развернуть стек либо сохранить без запуска.

Обработчик удаляет только служебную строку `name: <your project name>`, которую генерирует конвертер. Комментарии о неподдержанных параметрах сохраняются. Отчет помогает проверить результат, но не доказывает полную смысловую эквивалентность произвольной команды Docker и Compose.

В общей форме создания трех макетов есть только "Из Git" и "Вставить Compose". Распознавания команды, конвертера, отчета и возврата исходной команды там нет.

## Условия и состояния, которые нельзя потерять

- Операции управления относятся к стекам, управляемым Dockge. Обнаруженный сторонний стек не должен получать обещание полного управления только потому, что он появился в списке.
- Пока идет операция, повторные команды блокируются; результат может быть ошибкой или прерыванием. Мгновенная смена зеленой подписи в макете не моделирует это поведение.
- Сохраненный файл и фактически работающий стек могут отличаться. "Сохранить" и "Развернуть" должны оставаться разными действиями.
- `Stack.update()` обновляет образы. После загрузки он пересоздает стек только в состоянии RUNNING или ATTENTION; остановленный стек автоматически не запускает.
- Git-отставание в приложении вычисляется без сетевого fetch. Нельзя подписывать такие данные "проверено сейчас в Git" без соответствующей операции.
- Для include, специальных тегов, anchors и merge keys приложение отключает небезопасное структурное редактирование. Текстовый редактор остается доступен с пояснением. Эта защита сохраняется в новом интерфейсе.
- `down` и удаление стека различаются. `Stack.delete()` выполняет down с удалением оставшихся контейнеров проекта, затем рекурсивно удаляет каталог стека. Нельзя обещать сохранность данных, находящихся в этом каталоге.
- Секреты раскрываются отдельным действием с проверкой пароля. Демонстрационная подпись "скрыт" не заменяет этот сценарий.
- Потеря соединения, недоступный агент, пустой список, ошибка YAML и незавершенные правки требуют собственных состояний интерфейса.

Есть и более мелкие расхождения правил. Например, макет запрещает `_` в имени стека, хотя сервер разрешает его. Список будущих сервисов в макете всегда содержит web/broker/db даже после замены вставленного текста. Такие упрощения нельзя переносить в рабочее приложение.

## Как сохранить простоту

Предлагаемая общая структура подходит всем трем направлениям:

1. "Новый стек": два источника - "Compose / docker run" и "Из Git". В первом режиме одно поле распознает содержимое; преобразование показывает результат и отчет, позволяет вернуть команду. Далее имя, сервер, "Развернуть" и "Сохранить без запуска". Само преобразование ничего не запускает.
2. Шапка стека: состояние, запуск/остановка, перезапуск, обновление образов. Редкие операции раскрываются в меню. Git-обновление получает собственный вход в блоке источника.
3. Три вкладки: "Обзор", "Файлы", "Журнал". Сервисы и причины проблем находятся в обзоре; Compose, окружение и секреты - в файлах. В строке сервиса доступны его команды и оболочка.
4. Меню сервера: подключение агентов и консоль. Общее меню: настройки, учетная запись, повторное сканирование каталога.
5. Нижняя панель появляется при выполнении операции или открытой терминальной сессии. Для незавершенных изменений показывается явный выбор сохранить, развернуть или отменить.

Следующую редакцию трех макетов нужно сравнивать на одинаковом наборе сценариев: Compose, docker run, Git, редактирование и сохранение без запуска, обновление образов, конфликт файлов, ошибка выполнения, оболочка контейнера. Текущих трех экранов недостаточно, чтобы выбрать окончательный интерфейс всего продукта.
